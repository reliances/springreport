# JxReport / SpringReport 前端部署操作文档

> 目标读者：第一次接触本项目的运维 / 开发新人  
> 前端是静态资源，本身很简单；但必须和 Nginx、后端路径约定一致，否则会出现空白页 / 接口 404  
> 后端配套文档：`SpringReport_3/docs/后端部署操作文档.md`

---

## 0. 新人「付钱部署」前端部分能否顺利？

**只部署前端不够。** 登录、列表、文书都依赖后端 + Redis +（协同）RocketMQ + Oracle。  
新人完整路径请先看后端文档 **第 0 节交付物与总顺序**，再按本文打前端。

### 0.1 前端部署前必须具备

| # | 条件 | 说明 |
|---|------|------|
| 1 | 本机 Node **18+** / npm | 用于 `npm install` / `npm run build` |
| 2 | 工程 `SpringReport-ui-vue3/` | 含 `vite.config.js`（`base: '/JxReport'`） |
| 3 | 服务器 Nginx 已配好 | `location /JxReport/` → `/home/pub/vue/JxReport/dist/` |
| 4 | 后端 9099 已通 | 否则页面能开但接口失败 |
| 5 | 登录账号 | 向管理员索取（商户号 + 用户名 + 密码） |

### 0.2 前端最容易踩的坑

| 坑 | 结果 | 正确做法 |
|----|------|----------|
| `base` 与 Nginx 大小写不一致 | 空白页 / JS 404 | 统一 `/JxReport` |
| 上传到错误目录 | 404 | 必须是 `/home/pub/vue/JxReport/dist/` |
| 只 scp 了部分文件、没删旧文件 | 偶发旧缓存/脏文件 | 用 `rsync --delete` |
| 没配 `/SpringReport/api/` 反代 | 登录失败 | 见本文第 4 节 Nginx |
| 浏览器缓存 | 以为没发版成功 | 强制刷新 |

## 1. 先看懂前端在整套系统中的位置

```text
浏览器访问 http://<服务器IP>/JxReport/
        │
        ▼
Nginx :80
  ├─ /JxReport/**        → /home/pub/vue/JxReport/dist/   （本前端）
  ├─ /SpringReport/api/**→ http://127.0.0.1:9099/springReport/api/
  └─ /images/**          → /home/pub/datas/jxreport/images/
```

**路径约定（大小写不能错）：**

| 项 | 正确值 |
|----|--------|
| Vite `base` | `'/JxReport'`（注意大写 J、R） |
| Nginx location | `/JxReport/` |
| 服务器静态目录 | `/home/pub/vue/JxReport/dist/` |
| 前端请求 API 前缀 | `/SpringReport/api`（由 Nginx 反代到后端） |

> 错误示例（文档/历史里曾出现，不要再用）：`/jxReport`、`/JxkjReport`、`/SpringReport-v3`

### 环境对照（与后端 profile 对应）

| 环境 | 服务器 | 后端 profile | 访问地址 |
|------|--------|--------------|----------|
| 生产 | `172.20.20.94` | `prod` | `http://172.20.20.94/JxReport/` |
| 测试 | `172.20.20.45` | `test` | `http://172.20.20.45/JxReport/` |

前端打包产物相同；差别在 Nginx/后端指向的服务器与后端 `--spring.profiles.active`。

## 1. 部署前准备

### 1.1 本机需要

- [ ] Node.js（建议 **18+ / 20+**，当前常用 v20）
- [ ] npm（随 Node 安装）
- [ ] 能 SSH/SCP 到目标服务器
- [ ] 后端与 Nginx 已按《后端部署操作文档》装好（至少 Nginx + 9099 后端可通）

### 1.2 本机工程路径

```text
SpringReport-ui-vue3/                 # 前端工程根目录
├── src/
├── vite.config.js                    # base: '/JxReport'
├── package.json
├── dist/                             # npm run build 产物（要上传的）
├── offline-pkgs/                     # 离线安装包（后端/字体/Nginx 模板）
└── docs/前端部署操作文档.md          # 本文
```

### 1.3 服务器目录

```bash
# 首次部署先建目录
ssh root@<服务器IP> 'mkdir -p /home/pub/vue/JxReport/dist'
```

| 用途 | 路径 |
|------|------|
| 前端静态资源 | `/home/pub/vue/JxReport/dist/` |
| Nginx 配置 | `/etc/nginx/conf.d/jxkj-report.conf` |
| Nginx 访问日志 | `/var/log/nginx/jxkj-report.access.log` |
| Nginx 错误日志 | `/var/log/nginx/jxkj-report.error.log` |

## 2. 本机打包

### 2.1 确认 base 路径

打开 `vite.config.js`，确认：

```js
base: '/JxReport',
```

必须与 Nginx 的 `location /JxReport/` **完全一致**（含大小写）。

### 2.2 安装依赖并构建

```bash
cd /path/to/SpringReport-ui-vue3

# 首次或依赖变更时
npm install

# 生产构建
npm run build
```

成功标志：

- 命令退出码为 0
- 生成目录 `dist/`
- 其中至少有 `index.html`、`static/` 等

```bash
ls -la dist/
# 应看到 index.html、static/、luckysheet/ 等
```

### 2.3 构建失败常见原因

- Node 版本过旧 → 升级到 18+
- `npm install` 失败 → 检查网络/镜像，或使用已有 `node_modules`
- 内存不足 → 关闭其它占用后再 build

## 3. 上传到服务器

### 3.1 推荐：rsync 覆盖

```bash
cd /path/to/SpringReport-ui-vue3

# 先确保远端目录存在
ssh root@<服务器IP> 'mkdir -p /home/pub/vue/JxReport/dist'

# 同步（--delete 会删除服务器上多余旧文件，发版常用）
rsync -avz --delete dist/ root@<服务器IP>:/home/pub/vue/JxReport/dist/
```

### 3.2 或使用 scp

```bash
ssh root@<服务器IP> 'rm -rf /home/pub/vue/JxReport/dist/*'
scp -r dist/* root@<服务器IP>:/home/pub/vue/JxReport/dist/
```

### 3.3 上传后检查

```bash
ssh root@<服务器IP> 'ls -la /home/pub/vue/JxReport/dist/; test -f /home/pub/vue/JxReport/dist/index.html && echo INDEX_OK'
```

一般**不用重启 Nginx**。浏览器若仍是旧页面：强制刷新（Cmd/Ctrl + Shift + R）。

## 4. Nginx 配置（与前端强相关）

配置文件：

```text
/etc/nginx/conf.d/jxkj-report.conf
```

离线模板可参考：

```text
SpringReport-ui-vue3/offline-pkgs/jxkj-report-45.conf
```

### 4.1 完整推荐配置

```nginx
server {
    listen       80 default_server;
    server_name  _;

    # 前端静态资源（与 vite base: /JxReport 一致）
    location /JxReport/ {
        alias /home/pub/vue/JxReport/dist/;
        index index.html index.htm;
        try_files $uri $uri/ /JxReport/index.html;
    }

    location = /JxReport {
        return 301 /JxReport/;
    }

    # 后端 API（注意：对外 /SpringReport，后端上下文 /springReport）
    location /SpringReport/api/ {
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header REMOTE-HOST $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_pass http://127.0.0.1:9099/springReport/api/;
    }

    # 协同编辑 WebSocket
    location /SpringReport/api/coedit/websocket {
        proxy_pass http://127.0.0.1:9099/springReport/api/coedit/websocket;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host:$server_port;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 120s;
    }

    # 图片（与后端 file.path / file.url.prefix 对应）
    location /images/ {
        alias /home/pub/datas/jxreport/images/;
        charset utf-8;
        autoindex off;
    }

    location = / {
        return 302 /JxReport/;
    }

    access_log  /var/log/nginx/jxkj-report.access.log;
    error_log   /var/log/nginx/jxkj-report.error.log;
}
```

### 4.2 修改后生效

```bash
nginx -t
systemctl reload nginx
# 或
systemctl restart nginx
```

### 4.3 注意 `alias` + `try_files`

`location /JxReport/` 使用 `alias` 时，末尾斜杠、路径大小写必须正确。  
配错会出现：首页 404、刷新子路由 404、JS/CSS 404。

## 5. 前端依赖的后端服务

前端静态文件本身不依赖 Java，但**登录和业务**需要：

| 服务 | 端口 | 作用 |
|------|------|------|
| Nginx | 80 | 页面 + 反代 |
| JxReport | 9099 | 业务 API |
| Redis | 6379 | 后端会话/缓存等 |
| RocketMQ | 9876/10911 | 协同编辑等 |

若只传了前端、后端未起：页面可能能开，但登录/列表会失败。

后端部署见：`SpringReport_3/docs/后端部署操作文档.md`。

## 6. 访问与联调检查

在服务器上执行：

```bash
# 根路径应跳到前端
curl -sI http://127.0.0.1/ | head -5

# 前端首页
curl -sI http://127.0.0.1/JxReport/ | head -5
# 期望 HTTP/1.1 200

# 经 Nginx 调登录相关接口（后端需已启动）
curl -s -X POST http://127.0.0.1/SpringReport/api/login/getMerchantMode \
  -H 'Content-Type: application/json' -d '{}'

curl -s -X POST http://127.0.0.1/SpringReport/api/login/getMerchantList \
  -H 'Content-Type: application/json' -d '{}'
```

浏览器：

```text
http://<服务器IP>/JxReport/
```

登录页：多租户模式下应出现「商户号」下拉；账号密码默认为空，需手动输入。

## 7. 常见问题排查

### 7.1 打开页面空白 / 404

```bash
ls -la /home/pub/vue/JxReport/dist/index.html
grep -n "base:" vite.config.js          # 本机确认
grep -A5 'location /JxReport' /etc/nginx/conf.d/jxkj-report.conf
nginx -t
tail -n 50 /var/log/nginx/jxkj-report.error.log
```

核对三点：

1. `dist` 已上传且有 `index.html`
2. `base` 与 Nginx location 都是 `/JxReport`
3. `alias` 指向 `/home/pub/vue/JxReport/dist/`

### 7.2 JS/CSS 404

几乎都是 **base 与 Nginx 路径大小写不一致**。  
改 `vite.config.js` → 重新 `npm run build` → 重新上传 `dist`。

### 7.3 页面能开，接口 502 / 失败

```bash
ss -lntp | grep 9099
curl -s -X POST http://127.0.0.1:9099/springReport/api/login/getMerchantMode \
  -H 'Content-Type: application/json' -d '{}'
grep proxy_pass /etc/nginx/conf.d/jxkj-report.conf
tail -n 100 /var/log/nginx/jxkj-report.error.log
```

### 7.4 商户号下拉为空

```bash
curl -s -X POST http://127.0.0.1/SpringReport/api/login/getMerchantList \
  -H 'Content-Type: application/json' -d '{}'
```

需返回 `code=200` 且带商户列表。若 401，后端未放行登录商户列表接口。

### 7.5 协同编辑 WebSocket 失败

确认 Nginx 存在：

```nginx
location /SpringReport/api/coedit/websocket { ... }
```

并确认 RocketMQ、后端正常。

### 7.6 图片不显示

```bash
ls /home/pub/datas/jxreport/images/
curl -I http://127.0.0.1/images/
# 后端 application-*.properties 中 file.url.prefix 的 IP 必须是当前服务器
```

### 7.7 浏览器一直旧页面

强制刷新或清缓存；确认 `rsync --delete` 后服务器文件时间已更新。

## 8. 发版流程小结

### 日常只更新前端

1. 本机改代码  
2. 确认 `base: '/JxReport'`  
3. `npm run build`  
4. `rsync -avz --delete dist/ root@<IP>:/home/pub/vue/JxReport/dist/`  
5. 浏览器强制刷新验证  

### 新服务器首次（前后端一起）

1. 按《后端部署操作文档》装 JDK/Redis/MQ/Nginx/字体/后端 jar  
2. 配置 Nginx（本文第 4 节）  
3. 按本文打包并上传前端  
4. 打开 `http://<IP>/JxReport/` 登录验证  

### 回滚前端

用备份的上一版 `dist` 覆盖 `/home/pub/vue/JxReport/dist/` 即可。
